How it works

Lock. Work. Unlock.

One class to call, one interface to implement. Nothing else to learn.

1. Lock

$locker->lock('import') takes the lock, or returns false at once if another process holds it. Pass true to wait for it instead.

2. Work

Run the code that must never run twice at the same time: an import, a report, a counter, a payment.

3. Unlock

$locker->unlock('import'). Forgot it, or the script crashed? The lock is released when the Locker is destroyed and when the script ends.

Why Lock

Small enough to trust.

A lock guards your most sensitive code. It should be short enough to read in a few minutes.

No dependency

Pure PHP 7.4+, nothing else in your vendor/. No server, no extension: the default handler uses flock().

Never stuck

A file lock belongs to the process. If it dies, even killed, the system releases the lock. No stale lock to clean by hand.

Any backend

Need a lock shared by several servers? Implement LockHandlerInterface, two methods, on top of your database or Redis.

Safe keys

Keys accept letters, digits, _ and . only. A key can never become a path outside the lock folder.

Scope

What Lock will never do

One job: exclusive locks. Everything else belongs to your handler or your application.

  • add a dependency
  • require a server
  • retry on a timer
  • expire a lock behind your back
  • accept a key that is a path

Get Lock

One Composer command.
